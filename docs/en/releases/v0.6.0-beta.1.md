# Audux v0.6.0-beta.1 (internal candidate)

[Release notes](README.md) · [English documentation home](../README.md) ·
[简体中文](../../zh-CN/releases/v0.6.0-beta.1.md)

> Status: internal beta, not a public GitHub Release.

## Highlights

- Made transcript revisions immutable. Retranscription, segment correction, and full replacement
  create revisions; history remains readable but is no longer current search or agent evidence.
- Stored provider, model, language, redacted task configuration, glossary version, quality metrics,
  and parent revision on each revision.
- Made segments stable, playable, revision-bound evidence anchors; JSON exports gained revisions,
  chapters, and issues.
- Added manual chapter create/rename/boundary edit/merge/delete; chapters do not cross revisions.
- Added deterministic transcript issues for out-of-range, order, overlap, empty segment, full-text
  mismatch, suspected language, and low confidence, with required closure reasons.
- Defined ASR, LLM, and embedding provider contracts and probed structured/tool/streaming-tool output.
- Added a Pydantic Tool Registry with backend-injected scope and permissions; model arguments cannot
  supply roots, endpoints, tokens, or keys.
- Added privacy-free bilingual fixtures and reproducible synthetic WAV generation.
- Advanced the prerelease schema to v3 while retaining reject-without-migration behavior.

## Upgrade and boundaries

v0.5 data was not modified automatically. Validation used separate data and retained old builds and
snapshots. Automatic chapters, unified segment retrieval, and cited read-only agents moved to v0.7;
proposal approval and organization runs moved to v0.8.

The restore drill used 100 audio records and 600 revisions: snapshot at 500 revisions, add 100,
schedule restore with a safety snapshot, simulate restart, then verify 500 historical revisions and
100 unique current revisions—all in temporary data, never `~/.audux/`.
