# Audux v0.7.0-beta.1 (internal candidate)

[Release notes](README.md) · [English documentation home](../README.md) ·
[简体中文](../../zh-CN/releases/v0.7.0-beta.1.md)

> Status: internal beta, not a public GitHub Release.

## Highlights

- Added segment-level FTS5 for current transcript revisions with audio, revision, segment, time,
  matched field, context, and score.
- Added one scope resolver for whole library, current audio, selection, playlist, saved view, tag,
  and library root. Tool arguments cannot expand scope.
- Added persistent agent sessions, messages, runs, steps, tool calls, and citations on a dedicated
  worker separate from ASR/AI audio tasks.
- Added read-only search, audio, transcript segment, issue, tag, playlist, and statistics tools.
- Added session management, polling, cancellation, tool errors, export, and click-to-seek citations.
- Revalidated every citation against run scope, current revision, segment, and time at response time.
- Kept embeddings optional; unconfigured hybrid requests report `embedding_not_configured` and use
  FTS without disrupting ordinary search or transcript browsing.
- Advanced the prerelease schema to v4 without automatic migration.

## Evaluation and boundaries

`backend/evals/v0_7/` fixes bilingual queries, expected segments, and injection/leakage cases and
records Recall@5, first-result latency, citation coverage, unsupported-answer rate, and leakage.
Tests cover frozen scopes, FTS fallback, cancellation, citation playback, and revision invalidation.

An isolated 10,000-audio rehearsal measured 98 ms to first FTS result, 91 ms agent cancellation,
0.8 ms playback-record query, about 92 MB peak Python allocation, and 11.1 MB SQLite including WAL.
These are regression references, not hardware guarantees.

Embeddings were not yet selected; agents remained read-only. Organization runs and proposal
approval moved to v0.8. Target-OS interaction and installer testing remained manual release gates.
