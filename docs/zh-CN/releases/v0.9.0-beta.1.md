# Audux v0.9.0-beta.1（内部候选）

[发布记录](README.md) · [中文文档首页](../README.md)

v0.9 在既有的有据问答和整理闭环之上，加入受控低风险写操作、外部只读 MCP、可移植
归档与脱敏诊断。实现状态：**已完成**。此版本仍是内部候选，不代表公开发布或稳定兼容
承诺。

## 主要变化

- Agent 可以提案更新应用内 metadata、接受 Tag、加入手动 Playlist、创建保存视图和排队
  转写。后端冻结目标与 before/after、生成计划指纹，桌面端展示同一计划后才允许一次性批准。
- 执行前重新检查来源状态；目标变化、范围扩大或审批重放都会被拒绝。所有计划使用原子事务，
  任一项失败即全部回滚，并保留提案、批准、执行或失败审计。
- backend sidecar 增加 `--mcp` stdio 模式。MCP 仅发布 Tool Registry 的 read 工具，支持
  list/search/get audio/get Transcript/get Playlist/get statistics，并返回稳定 structured output
  与 citation id。可用 `AUDUX_MCP_AUDIO_IDS=1,2` 进一步收紧进程范围。
- 设置页可导出带版本 manifest 和 SHA-256 的当前格式归档；凭据、Token、绝对媒体根路径和
  音频文件不会进入归档。导入必须先 dry-run，只接受当前 schema，并在空资料库中事务执行；
  音频记录导入后标记为缺失，等待安全重新关联。
- 设置页可生成脱敏诊断包，只含版本、平台、白名单配置、任务状态摘要和数据库完整性结果，
  不含 Transcript、日志、API Key、Token 或绝对路径。
- 当前 schema 更新为 v6；预发布阶段不会迁移旧 schema 数据库。
- ASR/AI task、交互 Agent 和整理 Run 保持独立的单 worker 队列；Agent 与整理输入分别限制为
  24000 和每目标 12000 个转写字符，外部 ASR 切片并发上限为 4。整理 Run 在人工复核状态暂停，
  Tauri sidecar 或 stdio EOF 负责退出语义。诊断包会记录这份资源策略。

## MCP 启动

开发环境：

```bash
cd backend
uv run --locked python run.py --mcp
```

发布 sidecar 使用同一入口：

```bash
audux-backend-<target-triple> --mcp
```

stdio 只用于 JSON-RPC 消息，服务错误不会输出本地路径、Provider 配置或凭据。
