# Local Audio Library 功能路线图

> 更新于 2026-08-10。v0.x 版本号只表示内部 Beta 规划顺序，不是公开发布日期承诺；
> 每个阶段只有达到退出条件后才进入下一阶段。

## 当前判断

项目在 v1.0 前始终保留为内部 Beta，不创建公开 GitHub Release。`v0.5.0-beta.1` 等
版本字符串只用于内部候选、数据迁移和构建产物识别；GitHub Actions 手动构建产物用于
三平台验证，不对外发布。首次公开 Release 统一为 v1.0。

R1“创建备份—验证备份—安全恢复”闭环已经完成。当前下一项是 R2 保存视图，再将同一
版本化查询定义用于 R3 智能 Playlist。列表排序、错误本地化、browser-lite 发布形态和
Whisper companion 管理视为现有基础，不在路线图中重复建设。

## 排序原则

1. 数据可恢复性高于新模型能力；可能覆盖数据的功能必须先定义预检、事务、失败恢复
   和版本兼容语义。
2. 优先缩短整理、检索和播放的高频路径，复用已有筛选、任务和导出基础设施。
3. 本地能力是默认路径；远程 Provider 必须显式启用，并在发送音频或 Transcript 前
   说明范围。
4. AI 产出默认是建议，必须可检查、可拒绝、可重新生成，不能静默覆盖人工内容。
5. 每个里程碑同时交付数据模型、API、前端、迁移、回归测试和用户文档，不积累跨层
   欠账。
6. 新索引和衍生数据都必须可重建；删除、禁用媒体库目录和模型切换时要有明确同步
   语义。

## v0.5：核心工作流内部 Beta 基线

### F1：显式多选与批量整理（已完成）

- 音频列表支持单选、全选当前页、清空选择和可预测的选择清理规则。
- 对选中音频批量添加 / 移除标签、加入 Playlist、收藏 / 取消收藏。
- 后端批量写入使用明确事务，并返回逐项错误和汇总结果。

暂不包含：批量删除音频、批量修改文件路径、跨全部搜索结果的隐式全选。

### F2：Transcript 保真修订与搜索上下文（已完成）

- 支持逐段修改 Transcript 文本并保留时间轴，自动重建全文和 FTS 索引。
- 全文替换保留为明确清除分段的高级操作。
- 搜索结果展示相邻上下文并支持跳转播放；保存使用版本冲突保护。

暂不包含：手工修改时间戳、自动重新对齐、富文本和多人协作。

### F3：播放队列与会话连续性（已完成）

- 支持“下一首播放”“加入队列”、拖拽 / 键盘排序和队列持久化。
- 重启后恢复合法队列，跳过已删除、missing 或已禁用目录中的条目。
- 明确区分清空队列、停止播放和仅移除当前项。

### F4：范围收口评估（已完成）

结论：进入 Beta 发布验证，不追加 F5；只修复验证中发现的发布阻塞缺陷。数据库迁移
前备份、lite 安装包、可选 Whisper companion 和本地 API 加固已经达到候选版本范围。

### 内部验证门槛（持续执行）

- Linux、Windows、macOS 的安装包和 browser-lite 均完成 clean-install smoke test。
- 旧数据库升级、迁移前备份、较新 schema 拒绝降级修改均完成演练。
- 默认端口被占用、最后窗口关闭、任务取消时的后端 / companion 生命周期正确。
- release checklist 的自动化检查、安装包内容检查和人工验证门槛全部通过。
- 验证结果只用于修复和后续开发，不创建 v0.x 公开 Release。

## v0.6：数据恢复与可复用组织

### R1（P0）：手动数据库备份与安全恢复（已完成）

目标：用户不需要操作 SQLite 文件，也能完成一次可验证、失败时不损坏现有数据的
恢复。

范围：

- 在设置中列出、创建、命名、验证和删除应用管理的数据库快照。
- 为快照记录创建时间、应用 / schema 版本、大小、校验状态和来源；明确“数据库快照”
  不包含原始音频、模型缓存和导出文件。
- 恢复前检查文件完整性、schema 兼容性、磁盘空间和运行中任务，并显示将被替换的数据
  范围。
- 恢复操作先为当前数据库创建安全快照，再通过待恢复标记和应用重启完成切换；失败时
  回到原数据库并保留诊断信息。
- 所有备份路径由后端管理，不接受客户端传入任意文件路径。

验收门槛：

- 损坏、截断和较新 schema 的快照在写入前被拒绝。
- 恢复旧 schema 后只执行已有的向前迁移；恢复中强制退出不会同时破坏新旧两份数据。
- 音频、标签、Playlist、Transcript、任务历史和设置在恢复前后有自动化一致性检查。
- 后端覆盖状态机和失败注入测试，前端覆盖预检、二次确认、重启提示和错误恢复流程。

暂不包含：定时备份、云备份、同步、原始音频打包和选择任意外部恢复路径。这些属于
v0.9 的可迁移归档。

完成情况：后端提供受管快照清单、创建、校验、删除、恢复预检和待恢复状态 API；恢复
前阻止活动任务、验证磁盘空间和 schema，自动创建当前库安全快照。Tauri 在提交后自动
重启，browser-lite 提示手动重启；启动时执行原子切换，目标库初始化失败时自动回滚并
记录恢复结果。快照路径只能由后端解析，待恢复目标和安全快照均受删除保护。

### R2（P0）：保存视图

目标：把常用搜索、筛选和排序保存为一键可复用的资料库入口。

范围：

- 保存当前关键词、标签、收藏、Transcript / missing 状态、媒体库目录、排序方式和
  列表展示模式，并支持重命名、更新、复制、排序和删除。
- 视图定义持久化到数据库并带 schema 版本，不依赖某一浏览器的 `localStorage`。
- 引用的标签或媒体库目录被删除时，视图保持可打开，并明确提示已失效条件。
- 提供“应用视图”和“更新此视图”两个不同动作，避免浏览时静默改写定义。

验收门槛：

- 同一视图在 Tauri 和 browser-lite 中得到相同查询参数、数量和排序。
- 视图切换不会泄漏上一个视图的分页、选择或 Playlist 状态。
- 旧版视图定义可以迁移；无法识别的未来字段被安全忽略或明确拒绝。

### R3（P1）：智能 Playlist

目标：让动态条件集合具备 Playlist 的播放体验，同时不制造易过期的成员副本。

范围：

- 从保存视图创建智能 Playlist；成员在打开时根据当前资料库动态计算。
- 与手动 Playlist 在导航和视觉上明确区分，展示规则摘要、当前数量和最近刷新时间。
- 支持播放、加入队列和导出查询结果；智能 Playlist 本身只存规则，不写入静态关联。
- 复用统一的后端查询构造器，避免资料库、导出和智能 Playlist 对同一条件产生不同
  结果。

验收门槛：

- 扫描、标签修改、Transcript 状态变化后无需维护任务即可反映最新成员。
- 5000 条资料库上的计数和首屏查询保持可交互，并有查询索引 / 分页测试。
- 批量写操作仍要求显式选择；智能 Playlist 不恢复“隐式操作全部结果”的行为。

依赖：R2。若无法复用同一查询定义和后端查询构造器，不开始实现 R3。

### R4（P1）：资料库健康中心与安全重新关联

目标：集中解释 missing、禁用目录、扫描失败和疑似重复项，并提供不删除原文件的修复
路径。

范围：

- 汇总各媒体库目录的可用、missing、扫描失败、未支持格式和最近扫描状态。
- 对移动后的文件提供候选重新关联；候选必须位于已配置目录内，并校验大小、时长和
  可用 metadata，不能只按文件名自动匹配。
- 首版重复检测使用低成本候选规则，并把内容哈希作为用户主动执行的确认步骤，避免
  扫描时默认读取全部大文件。
- 修复前预览对 Transcript、标签、Playlist、封面和播放记录的影响；默认不删除磁盘
  文件或数据库记录。

验收门槛：

- 路径校验不能绕过媒体库根目录限制，符号链接和大小写差异有平台测试。
- 重新关联在一次事务内保留现有用户数据并同步 FTS；冲突时不做部分写入。
- 健康检查可取消、可重试，不阻塞播放和普通分页查询。

### R5（P2，可整体顺延）：Transcript 章节

目标：为长音频提供比全文滚动更快的导航方式。

范围：

- 章节绑定 Transcript 修订版本，包含标题、起止时间和可选摘要。
- 支持手工创建、重命名、调整边界、合并和删除章节。
- 自动章节和 AI 摘要作为后台建议任务，用户确认后才替换现有章节。
- 搜索命中、章节列表和播放器时间轴可以互相跳转。

验收门槛：

- Transcript 被重新转写或清除时间轴时，旧章节不会静默指向错误时间。
- 无 LLM 或离线环境仍能手工使用章节；AI 失败不影响 Transcript。
- 章节导出至少包含稳定 JSON 格式，后续可用于 v0.8 引用。

若 R1–R4 尚未稳定，R5 整体顺延到 v0.7，不压缩恢复和健康检查的验证时间。

### v0.6 退出条件

- 使用真实规模测试库完成一次“创建快照—修改数据—恢复—校验”的人工演练。
- 保存视图与智能 Playlist 共用查询语义，不出现两套筛选实现。
- 健康中心的任何默认动作都不删除原始音频或不可恢复地合并记录。
- 完成数据库迁移、路径安全、事务回滚、跨前端行为和视觉回归测试。

## v0.7：Transcript 增强与可解释的语义检索

### S0：技术验证与质量基线

- 用匿名或可公开分发的中英混合样本建立 FTS 基线、查询集和期望命中。
- 比较 embedding 模型的语言质量、CPU 延迟、内存、磁盘和安装 / 首次下载体积。
- 先定义 `EmbeddingProvider` 与索引存储边界，再决定 SQLite 扩展、独立索引文件或其他
  实现；路线图不预先绑定向量数据库产品。

退出条件：形成可复现评测和架构决策记录，证明语义能力值得增加的体积与复杂度。

### S1：本地 embedding 与索引生命周期

- 以 Transcript 分段为主要单元，并为标题、作者、描述和标签保留可解释字段来源。
- 索引记录模型、维度、分块策略和源内容版本；支持增量更新、取消、断点恢复和全量
  重建。
- 音频 / Transcript 删除、重新转写、目录禁用和模型切换都有确定的失效与回收规则。
- 索引是可重建衍生数据，不进入数据库恢复的唯一可信数据范围。

### S2：FTS + metadata + embedding 混合检索

- 默认混合精确关键词、标签 / metadata 过滤和向量相似度，不用语义搜索取代 FTS。
- 结果显示命中来源、Transcript 上下文、时间戳和可跳转播放入口。
- 模型不可用、索引未完成或资源不足时自动退回现有搜索，并清楚显示当前模式。
- 提供“仅关键词 / 混合检索”切换和索引管理，不让后台下载在无提示时发生。

验收门槛：

- 固定查询集的相关性相对纯 FTS 有可测提升，同时不降低精确标题 / 标签查询质量。
- 1 万条音频规模下首个结果延迟、后台索引 CPU / 内存和磁盘占用有记录的上限。
- 删除数据后旧向量不可再检索；索引损坏时可以从可信数据完整重建。

暂不包含：必须联网的 embedding、跨设备向量同步和问答生成。

## v0.8：基于 Transcript 的有据问答

### Q1：限定范围的检索与回答

- 按保存视图、Playlist、标签、媒体库目录、当前音频或显式选择集限定范围。
- 回答中的事实性结论必须关联 Transcript 片段和时间范围，并可直接跳转播放。
- 证据不足、Transcript 缺失或检索结果互相冲突时明确说明，不生成无来源结论。

### Q2：会话、Provider 与隐私

- 问答会话默认只保存在本地，可重命名、删除和导出；删除后同步清理关联引用。
- 默认使用本地模型。远程 endpoint 每次显示将发送的音频范围 / Transcript 字符量，
  继续沿用显式授权和凭据脱敏规则。
- 长任务进入现有任务系统，支持进度、取消、重试和应用重启后的 interrupted 状态。

### Q3：质量评测

- 建立“答案是否被引用支持、引用时间是否正确、范围过滤是否泄漏”的回归集。
- UI 区分引用原文、模型概括和模型不确定性；不能用流畅度代替正确性。
- Provider 不可用时仍可浏览既有 Transcript 和搜索结果，不影响核心资料库能力。

暂不包含：访问互联网、代表用户修改文件 / metadata 的 Agent、多用户共享会话和无引用的
开放式聊天。

## v0.9：可迁移归档与发布硬化

- 定义带版本 manifest 的可迁移归档，覆盖 metadata、标签、手动 / 智能 Playlist、
  Transcript、章节、保存视图和必要设置；凭据与本地 API token 默认永不导出。
- 导入先 dry-run，报告 schema、缺失音频、ID / 路径冲突和合并策略，再执行事务化写入。
- 默认只记录音频引用；“连同原始音频打包”作为空间预估清楚的显式选项单独评估。
- 增加诊断包和“资料库 doctor”：只收集脱敏配置、版本、日志摘要和完整性结果。
- 改善扫描、ASR、embedding 和迁移的细粒度进度、取消及异常退出恢复。
- 对 Tauri 与 browser-lite 执行长期运行、升级、休眠恢复、端口冲突和大资料库测试。

验收门槛：至少用前两个受支持版本的测试归档完成跨版本导入；诊断包不包含 token、API
key、完整 Transcript 或用户绝对路径；三个桌面平台的安装、升级和卸载矩阵可重复执行。

## v1.0：稳定桌面版本

v1.0 是质量门槛，不再堆叠新的大型功能。发布前必须满足：

- 明确支持的操作系统、数据库 / 归档版本和向前迁移策略。
- 完整备份、恢复、导入、导出和损坏诊断流程均有文档与回归测试。
- 核心播放、整理和关键词搜索不依赖 AI、网络或可选组件。
- Provider 接口稳定，隐私提示、凭据存储、日志脱敏和删除语义经过安全复核。
- 建立稳定发布节奏、弃用周期、已知限制和回滚指引。

## 候选池：需要验证，不承诺版本

以下功能有价值，但只有在完成用户研究或技术验证后才进入正式里程碑：

- 说话人分离与说话人重命名：需要先确认不同 ASR Provider 的时间轴兼容性。
- Transcript 时间戳手工修订和自动重新对齐：需要可撤销编辑模型与导出兼容方案。
- 书签、片段和个人注释：需验证它与章节、搜索结果和播放队列的交互是否足够简单。
- 波形预览与片段导出：需评估衍生缓存大小、解码成本和版权 / 隐私提示。
- 文件夹监视与自动扫描：需处理跨平台文件事件、移动检测和大量事件合并。
- 全局媒体键、迷你播放器和系统托盘：按平台分别验证，不能破坏后端退出语义。
- 插件式模型接口：先稳定 ASR、embedding 和 LLM Provider 的最小公共边界。

当前不规划云同步、移动端、多人协作、内置模型商店和会修改磁盘原文件的音频编辑器；
这些方向会显著改变本地单用户产品边界，应通过独立提案重新评估。

## 建议立即启动的工作

1. 持续执行三平台内部 Beta checklist，但 v0.x 不创建公开 Release。
2. 在 R2 开发前整理当前所有筛选 / 排序参数为单一版本化查询定义，为智能 Playlist
   和后续问答范围复用同一契约。
3. 实现 R2 保存视图的数据库迁移、查询定义 API 与 Tauri/browser-lite 一致性测试。
4. 使用接近真实规模的测试库补做 R1 人工“创建—修改—恢复—校验”演练，并保留结果
   作为 v1.0 数据恢复发布证据。
