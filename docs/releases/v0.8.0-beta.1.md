# Audux v0.8.0-beta.1（内部候选）

v0.8 建立“转写 → 验证 → 有证据提案 → 人工审批 → 事务回写 → 再验证”的整理闭环。
此版本仍是内部候选，不代表公开发布或稳定兼容承诺。

## 主要变化

- 新增持久化整理 Run。创建时冻结目标音频 ID 和来源 Transcript revision，并记录
  `preflight → transcribe → validate → review → enrich → apply → reindex → verify` 八个阶段。
- 新增整理工作台，可从当前音频、选择集、Playlist、保存视图、Tag、媒体库目录或全库
  创建 Run，查看逐阶段数量、失败项、待审批数和发送给 Provider 的转写字符量。
- 勘误、Tag、描述和章节建议均保存来源 revision、支持 Segment、理由、置信状态与审计事件；
  勘误额外展示字符级 diff。
- 支持逐项接受、编辑后接受、拒绝和跳过，并可从证据时间点播放。正式写入按类别触发，
  不提供绕过类别影响预览的“全部接受”。
- 接受勘误会在一个事务中创建新的不可变 revision、同步全文和 FTS；Tag、描述和章节与
  同一批写入共同提交。revision 冲突或索引失败时不会留下半写入结果。
- 当前 revision 变化时，尚未应用的旧提案自动标记 stale；旧 Agent 引用继续由既有的
  当前 revision 校验阻止展示。
- 确定性重新校验会报告已关闭、仍存在和新出现的 issue；诊断摘要只包含有界元数据和
  issue 证据，不包含 API Key、本地 API token、绝对路径或完整 Transcript。
- 活动中心聚合整理 Run；异常重启把执行中的 Run 标为 interrupted，由用户显式重试。
  数据库恢复预检会阻止活动或待审批 Run 被静默切断。

## 数据与兼容性

- 当前预发布 schema 版本更新为 5。
- 按 pre-v1.0 策略，不迁移或自动修改旧 schema 数据库；版本不匹配时拒绝启动。
- 应用版本统一更新为 `0.8.0-beta.1`。

## 验证重点

- 冻结范围不会吸收 Run 创建后新增的音频。
- 手工修订后旧提案不能再接受或应用。
- 同一输入不会在同一 Run 内产生重复提案。
- correction、Tag、描述、章节的组合应用与全文索引更新保持事务一致。
- 取消、失败、重启中断和数据库恢复预检保留可审计状态。

## 暂不包含

- 自动修改原始音频内嵌 metadata。
- 无证据的开放式写操作、任意文件操作、互联网访问或外部 MCP 写工具。
- v0.9 规划中的低风险操作 Agent 与发布硬化。
